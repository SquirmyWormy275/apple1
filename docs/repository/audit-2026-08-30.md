# Repository-wide audit — 2026-08-30

## Scope and baseline

This audit is the repository-wide consolidation pass requested after NEURAL1 Pilot 001, the 1976 MULTIVERSE research integration, and the display/Sanyo research work. It does not replace the earlier NEURAL1 foundation audit at `docs/neural1/audit-2026-08-30.md`.

Live GitHub `main` at the start of implementation was:

```text
3c06a857b93409e4c681e1d794fa757bf66db3cc
```

The handoff included an older Git metadata snapshot whose `origin/main` was `3d440fa8e754bef2a4fbc4803236da08dfdba668`; live GitHub was 28 commits ahead of that snapshot. The audit therefore treats live GitHub as current and the bundled Git data only as secondary archaeology evidence.

The remote API cannot prove the state of an arbitrary developer checkout, local stash, or local worktree. The bundled checkout metadata showed no separate worktree or stash refs. No destructive cleanup was performed.

## Repository identity

The repository is one project with six authority domains that must not be collapsed:

1. **Apple-1 preservation** — captured and externally sourced evidence, manifests, manuals, candidate firmware, hardware investigation, and recovery records.
2. **COMPUTER mode** — ordinary Apple-1 / Replica-1 computing, independent of NEURAL1.
3. **Field Library** — source-grounded educational material and deterministic rehearsal evidence.
4. **NEURAL1** — virtual-first experimental-computing runtime and five experiment families.
5. **META/1** — claims, evidence, falsification, tribunals, research queues, causality, proof capsules, and replication state.
6. **1976 MULTIVERSE historical corpus** — research staging plus a deliberately gated future authoritative runtime corpus.

## Documentation map and consolidation findings

### Already well-separated

- `docs/field-library/` is a product-like corpus with lesson packets, source notes, answers, teacher material, visitor material, program annotations, and emulator evidence.
- `docs/neural1/` already separates architecture, experiments, META/1, interface, research, publications, decisions, benchmarks, and history ingestion.
- `docs/peripherals/displays/` has its own evidence ledger, rights ledger, source register, open-research queue, validation record, Sanyo sub-tree, and visual chronology.
- `docs/collection/sanyo-vm-4209-1979/` correctly separates collection accession/provenance from general display history.
- `docs/captures/` keeps serial STOP evidence and future logic-analyzer paperwork as evidence artifacts rather than normal tutorials.

### Similar names that are not duplicates

- `docs/neural1/research/research-agenda.md` is a concise conceptual agenda; `research-agenda-v1.md` is the detailed research tranche. They have different roles and should not be merged by filename similarity.
- General `negative-results.md` and Pilot 001 `negative-results.md` have different scopes.
- `docs/neural1/audit-2026-08-30.md` is a historical foundation audit; this repository audit has a wider scope and should coexist.
- `cf-card/` and `preservation/cf-card/` are intentionally different: control/export source versus immutable captured baseline.

### Stale or misleading status

`docs/plans/2026-08-25-1324-fix-replica1-propeller-serial-plan.md` declares itself `implementation-ready`, but the repository subsequently recorded a STOP result showing that an ordinary no-transmit FT232R open disturbed the machine. The plan is historically useful but its front matter can mislead a current reader into treating later physical steps as approved. This architecture pass marks it superseded/blocked without deleting its original plan content.

### Field Library

The current Field Library index reports 41 lesson packets. H06 has passed its review gate; the pre-existing forty packets have not been reviewed as a set and the index retains an open verification item for that corpus. The audit therefore treats the corpus as authored educational source, not as automatically approved CF-card export content.

### Pilot 001

Pilot 001 is committed scientific evidence. Its current package accurately records:

- 45 planned cells, 6 completed;
- cooperative thermal stop at 102 C;
- 156 recorded turns and zero strict-parser acceptances;
- a bounded resume that completed one interrupted SmolLM2 cell;
- no automatic scientific findings;
- `physical_serial_opened: false` and all other physical-write safety flags false.

It must remain prominently addressable as the first model-validated pilot and must not be rewritten as a successful full model comparison.

## 1976 MULTIVERSE authority review

The repository currently has the desired gate:

```text
RESEARCH_STAGING
    -> source artifact acquired
    -> SHA-256 verified where policy requires it
    -> claim extracted
    -> claim reviewed
    -> cutoff validated
    -> provenance/evidence quality accepted
AUTHORITATIVE HISTORICAL CORPUS
```

Current `data/neural1/history/1976-research-index.json` says:

- `status = RESEARCH_STAGING`;
- `authoritative_runtime_records = 0`;
- `runtime_authoritative_component_ids = []`;
- SHA-256, claim review, and cutoff validation are required;
- missing prices remain null;
- LLM estimates are forbidden.

`neural1.history.load_research_index()` independently enforces those policy flags and rejects authoritative IDs in a staging corpus. No promotion is justified by this audit.

## Source versus generated output

The durable classification is:

| Class | Typical locations | Git policy |
|---|---|---|
| SOURCE | `neural1/`, `tools/`, `software/`, `configs/`, `schemas/`, authored docs | Commit. |
| AUTHORITATIVE DATA | Future reviewed historical component corpus; selected machine-readable evidence | Commit only after domain gate. |
| RESEARCH STAGING | `data/neural1/history/` and explicitly staged research docs | Commit with visible non-authoritative status. |
| TEST FIXTURE | `neural1/fixtures/`, test-created temporary data | Commit fixtures; do not confuse with observations. |
| GENERATED OUTPUT | default `out/`, local `.neural1/` | Do not commit unless deliberately promoted to evidence. |
| PRESERVED ARTIFACT | `preservation/`, provenance-sensitive vendor source | Commit/LFS with hashes and provenance; do not modernize in place. |
| DERIVED DOCUMENTATION | `docs/`, `wiki/`, explanatory reports | Commit, but link back to source/evidence and state limitations. |

Pilot 001 is an explicit exception to the ordinary generated-output rule because its package is intentionally committed scientific evidence.

## Provenance and rights findings

### Strong / complete enough for current role

- Candidate Replica 110REV03 firmware has source URL, archive identity, retrieval date, per-file hashes, candidate properties, and explicit non-EEPROM limitations.
- CF-card baseline has preservation manifests and a non-destructive export architecture.
- Apple1-Slideshow is pinned to a commit and explicitly blocked from redistribution because no license grant was found.
- Display/Sanyo research has a dedicated evidence and image-rights ledger; seller and auction images are link-only unless rights allow reuse.
- The 1976 staging index separates hash-verified source acquisition from claim authority.

### Incomplete / review needed

- Several preserved manual PDFs are externally authored copyrighted works. Their preservation README records owner authorization to place supplied copies in public GitHub, but that is not equivalent to a copyright redistribution grant. The display rights ledger separately treats at least the Apple-1 Operation Manual scan as link-only absent redistribution permission. Preserve the evidence and record this as a rights-review gap; do not invent a license.
- The Field Library itself carries a long open-verification register. Those entries remain open unless specifically resolved from evidence.
- Historical candidate sources blocked on acquisition/hashing remain candidates only.

## Schema/data-contract review

The schema tree is compact and coherent. `campaign`, `historical-research-index`, and `model-registry` have committed instances validated by `tools/neural1_validate.py`. `checkpoint`, `release-bundle`, and `run-manifest` describe runtime/generated evidence types, so lack of a permanent root instance is not evidence they are dead. The key structural gap is validation coverage: the repository validator historically checks Markdown links only in selected NEURAL1/visual/art/wiki trees instead of all first-party Markdown.

## Major risks

1. **Authority collapse:** treating research notes or lesson prose as runtime historical truth.
2. **Preservation mutation:** editing preserved firmware/manual/image bytes to make documentation cleaner.
3. **Physical-boundary regression:** running or normalizing a serial-capable tool because it exists in source control.
4. **Rights overreach:** confusing public availability, ownership of an object, or owner authorization with third-party copyright permission.
5. **Documentation drift:** many valid sub-products without a single durable project map.
6. **Branch misclassification:** interpreting diverged research/archive history as missing production content or deleting it because equivalent blobs reached main through another lineage.

## Audit conclusion

The repository does **not** need a wholesale directory rewrite. Its current substantive domain boundaries are already mostly correct. The durable rebuild should therefore be conservative:

- add a repository governance/navigation layer;
- make authority classes explicit;
- strengthen validation around repository structure and links;
- mark the old physical serial repair plan as historically superseded/blocked;
- document branch archaeology and rights gaps;
- leave preservation, Pilot 001, 1976 staging, Field Library content, and working NEURAL1 package paths stable.

That is a structural rebuild because it establishes enforceable ownership and authority boundaries without creating churn merely to produce a prettier tree.
