# 12. Build an inspectable constrained-computing exhibit

Your capstone is a small, explainable program and an evidence package. The goal
is that another learner can predict it, run it, and evaluate your claim.

## Stage 1: specify

Choose a bounded task: fill five bytes, copy a short nonoverlapping buffer,
classify one input byte, or output a character and return. Write inputs, outputs,
memory ranges, clobbered registers, exit, instruction bound, and limitations.
Do not begin with "make an intelligent agent"; begin with an observable task.

## Stage 2: implement and predict

Work from A06 in a scratch copy. List instruction addresses and generated bytes.
For a loop, calculate the relative branch base and displacement. Predict final
registers and memory, including the first byte outside the intended range.
Specify binary/decimal and carry assumptions explicitly when using ADC/SBC.

## Stage 3: execute and challenge

Run through the existing bounded virtual world. Retain the trace and raw result.
Test at least a normal case, an empty or minimum case, a maximum/boundary case,
and an intentionally invalid candidate. A passing positive case and a rejected
negative control are both part of your evidence.

## Stage 4: add the model proposal boundary

First use L04/F03's fixed-response or replay provider. Demonstrate what the parser
accepts and refuses. Do not call that model inference. If you later use a real
qualified local model, record its identity and configuration and retain its exact
responses; compare its actual behavior with the same predeclared evaluator.
A model explanation does not replace the machine trace.

## Stage 5: recover and package

Demonstrate snapshot restore or checkpoint resume using F14 or F05. Export a
copy and verify it using F06. Change a disposable exported byte and confirm
rejection without altering the original reference. Explain exactly which
artifacts identify the run, which preserve state, and which carry a claim.

## Stage 6: teach and present

Create a short README with problem, result, run command, expected output,
source/dependency attribution, evidence links, and limitations. Include one
readable capture. Build a two-minute explanation from X03 and a source/evidence
card from H03/X04. Someone should be able to inspect your contribution without
running a model or connecting hardware.

## Rubric (0–2 points each)

| Criterion | 0 | 1 | 2 |
|---|---|---|---|
| Task contract | Vague goal | Some inputs/results named | Inputs, bounds, memory, exit, and limits explicit |
| Prediction | No prior prediction | One final value | Instruction/state reasoning plus boundary prediction |
| Implementation | Unreproducible | Runs once | Source/bytes retained and routine meets its contract |
| Controls | Positive only | One negative case | Meaningful positive, negative, and boundary checks |
| Evidence | Screenshot only | Output and source | Raw output, identities, hashes, and reproduction steps |
| Interpretation | Overclaims | States one limit | Separates host, virtual, synthetic, native, and physical evidence |
| Communication | Unclear | Usable instructions | New reader can understand, run, and explain a variation |

A score is a review aid, not a scientific maturity label. Keep the reviewer's
comments and revise the weakest area. Finish by writing what you would investigate
next and what new evidence would justify it.
