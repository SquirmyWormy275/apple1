# 11. Preserve the evidence and teach it accurately

An educational system needs more than working code. It needs source identity,
rights, precise object names, and captions whose conclusions match the evidence.
These habits also make a repository easier for an employer or collaborator to
review.

## A source is not every kind of proof

A manual documents a design. A scan records a copy of a document. A checksum
identifies bytes. A transcript records an interaction in an identified setting.
A physical observation describes a particular unit and procedure. None can
silently substitute for the others.

H01–H06 teach timeline claims, object labels, provenance, experimental boundaries,
collection logs, and display associations. SP01 compares original and replica
subsystems while retaining uncertainty about this unit. The new host exercises
check their own arithmetic and record structure; they do not independently
verify every historical statement in the source pool.

## Keep original records and derived lessons distinct

The Field Library's verification register remains open where it was open.
Adding a worked example does not close V-36's earlier set-level historical review
or make a packet approved for physical CF deployment. The reset-vector error
found during this work is corrected explicitly and linked to a primary manual;
its quoted secondary source remains visible as an erratum.

For B05/F22, a file can be content, executable source, or a recovery copy depending
on how it is used. Host-side staging has an approval manifest. It is not a card
writer and does not establish a physical launcher.

## Publish a useful demonstration

X03 plans a three-minute tour with one idea and an unpowered fallback. X04 builds
an exhibit argument from three artifacts, each with a "what this does not prove"
field. X05 asks you to write an observable objective and a reviewable activity.
A reviewer should see what you implemented, what you reused, what worked, and
what remains unresolved.

F19 checks the original ASCII portal frame. Formatting validity does not grant
redistribution rights to outside artwork. Use the project's provenance and
rights records before reusing heritage imagery; an attractive image is not a
license. The capture images in this book are generated from project stdout,
not copied third-party artwork.

## Assess an explanation

A learner should identify the task, point to the relevant byte or record, explain
the causal step, reproduce a result, test a boundary, and state a limitation.
Do not award understanding solely for running a command or copying an answer.
Ask the learner to predict a small variation before executing it.

The [capstone and rubric](12-capstone.md) tie assembly, model proposals,
verification, and clear communication into one portfolio-quality piece of work.
