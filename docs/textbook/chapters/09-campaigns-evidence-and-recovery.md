# 9. Make a run recoverable and a claim inspectable

Research work becomes useful to another person when its identity, state, and
evidence can be reconstructed. A successful launch is only the start.

## Manifest, transcript, snapshot, checkpoint

A manifest records canonical inputs. The transcript records model/Monitor
exchanges. A snapshot records machine state. A checkpoint records progress and
the snapshot/transcript identities needed for recovery. An export packages
retained evidence with a manifest of file hashes.

Run F14 to snapshot and restore a changed world. A fork records its parent,
fork point, and changed factor. Neither a restoration nor a fork should be an
invisible correction of a failed experiment.

## Resume the same work

F05 requests cancellation after the first synthetic provider call, then resumes
with the actual campaign engine. The committed prefix must remain intact and
the final transcript must contain three turns, not a duplicated first turn.
This is a host fixture, not a demonstration of a Pi service surviving logout.
Native lifecycle observations remain in the commissioning closeout.

In the operator application, `RUNS`, `STATUS`, `SHOW run-id`, and
`TRANSCRIPT run-id [page]` answer different questions. Page 0 begins a transcript;
without a page, the command shows the latest bounded slice. `STOP run-id` requests
owned cancellation; `RESUME run-id` continues recorded work with the effective
registry. `QUIT` leaves active workers running.

## Verify an export before interpreting it

F06 verifies an export, alters a disposable copy, and observes verification fail.
A matching hash supplies byte identity, not truth or authenticity. Keep raw
records and derived interpretations distinguishable. A report may summarize an
export; it must not silently replace it.

`EXPORT run-id` and `OPEN bundle-path` work with the commissioned SSD in the
operator console. Developer `export-bundle` and `verify-bundle` operate on named
host directories. The synthetic F06 example supplies safe temporary paths.

## Read META as evidence relationships

F07 creates a synthetic claim, persists evidence and a supporting edge, queries
history, and compares rule-based tribunal thresholds. The verdict changes when
the required evidence level changes. An authored fixture causal level is not a
causal discovery. Human review of the evidence still matters.

`META`, `META CLAIM`, `META HISTORY`, and `META QUEUE` expose stored records.
The separate `neural1-meta` CLI also supports tribunal and historical-sequence
queries. Review the full command coverage register before choosing an operator
path instead of a host fixture.

## Rebuilding a SELFHOST artifact

F23 builds a deliberately synthetic stage-one archive, reconstructs its bytes,
and verifies an export. Later `SELFHOST QUALIFY` work requires qualified parents,
a retained builder, repeat reconstruction, and declared behavioral controls.
A stage-one pass is not an assembler. `INGEST`, `REBUILD`, `QUALIFY`, `EXPORT`,
and `OPEN` have distinct evidence roles; keep their operation receipts.

## Practice

Hand a reviewer your prediction, source revision, exact command, raw output,
and capture manifest. Ask them to reproduce it. Then alter one disposable byte
and confirm that verification notices. Preserve the original reference.
