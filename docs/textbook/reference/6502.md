# NMOS 6502 desk reference

Use this alongside [chapter 4](../chapters/04-assembly-and-control-flow.md), not
as a substitute for worked reasoning. The execution model is Py65's NMOS 6502;
the Replica's installed CPU/ROM identity and electrical behavior require their
own records. Undocumented opcodes and later 65C02 extensions are outside this
course's contract.

## Register and status map

A, X, Y and SP hold eight bits; PC holds sixteen. P's bits, from 7 to 0, are
N, V, a reserved status-stack convention, B's status-stack convention, D, I, Z, C.
Do not treat B and the reserved bit as independent persistent interrupt hardware
latches merely because a software model exposes them in P.

| Flag | Question |
|---|---|
| N | Is bit 7 of the relevant result set? |
| V | Did signed arithmetic exceed the representable range? BIT has separate V semantics. |
| D | Is decimal adjustment enabled for ADC/SBC? Establish CLD for the binary lessons. |
| I | Are maskable IRQs disabled? This is separate from NMI. |
| Z | Is the relevant result zero? |
| C | Addition carry, subtraction no-borrow, or the shifted/rotated-out bit? |

Instructions set specific flags; they do not all set every flag. STA does not
change flags. LDA changes N/Z, CMP changes N/Z/C, ADC and SBC change N/Z/C/V in
binary mode. BIT sets Z from A AND memory, and N/V from memory bits 7/6. NMOS
decimal-mode flag details require the CPU reference; do not transfer a binary
flag explanation unchanged to SED arithmetic.

## Documented instruction families

These rows contain all 56 documented NMOS instruction mnemonics. Availability
of an addressing mode varies by instruction; a row does not imply every form.

| Family | Mnemonics | Job / caution |
|---|---|---|
| Load/store | LDA LDX LDY STA STX STY | Load a register or store it in memory |
| Register transfer | TAX TAY TSX TXA TXS TYA | Copy registers; TXS preserves flags |
| Stack | PHA PHP PLA PLP | Push/pull A or status; balance data with call frames |
| Arithmetic | ADC SBC | Include C; D selects decimal adjustment |
| Comparison | CMP CPX CPY | Set comparison flags without replacing the compared register |
| Bitwise | AND EOR ORA BIT | Mask, flip, set, or test bits |
| Shift/rotate | ASL LSR ROL ROR | Move a bit through C; rotates also consume C |
| Increment/decrement | INC INX INY DEC DEX DEY | Change a memory byte or index register |
| Conditional branch | BCC BCS BEQ BMI BNE BPL BVC BVS | Test C, Z, N or V; relative signed displacement |
| Transfer/call/return | JMP JSR RTS | JMP does not create a call frame |
| Interrupt | BRK RTI | BRK uses IRQ/BRK vector; RTI restores status and PC |
| Status control | CLC CLD CLI CLV SEC SED SEI | Establish selected status bits |
| No operation | NOP | Still advances PC and consumes execution work |

Multiplication and division require algorithms; there is no documented NMOS
MUL or DIV opcode in this inventory. Avoid estimating a program's physical
speed by counting source lines. Addressing mode, taken branches, page crossings,
clocking and implementation all matter.

## Addressing forms

| Form | Example | Operand interpretation |
|---|---|---|
| Implied | `DEX` | Register/action implied by opcode |
| Accumulator | `ASL A` | Operate on A |
| Immediate | `LDA #$41` | Byte value in instruction |
| Zero page | `LDA $20` | Byte at `$0020` |
| Zero page,X | `LDA $20,X` | Address `(base+X) & $FF` |
| Zero page,Y | `LDX $20,Y` | Address `(base+Y) & $FF`; mode supported by selected instructions |
| Absolute | `LDA $0400` | Byte at a 16-bit address |
| Absolute,X | `LDA $0400,X` | Add X to base |
| Absolute,Y | `LDA $0400,Y` | Add Y to base |
| Relative | `BNE LOOP` | Signed displacement from PC after branch |
| Indirect JMP | `JMP ($0400)` | Read target address through memory |
| Indexed indirect | `LDA ($20,X)` | Index within zero page, then dereference pointer |
| Indirect indexed | `LDA ($20),Y` | Dereference zero-page pointer, then add Y |

A zero-page pointer's high byte wraps from `$FF` to `$00` within zero page.
For NMOS `JMP ($12FF)`, the high target byte is read from `$1200`, not `$1300`.
That particular indirect-JMP behavior differs on later CPUs. Most beginner
routines should choose a pointer location that avoids the boundary.

## Vectors and entry points

| Mechanism | Where / what |
|---|---|
| NMI vector | Low/high bytes at `$FFFA/$FFFB` |
| RESET vector | Low/high bytes at `$FFFC/$FFFD` |
| IRQ/BRK vector | Low/high bytes at `$FFFE/$FFFF` |
| Monitor warm entry used by these programs | JMP to `$FF1F`; no CPU reset implied |
| Monitor ECHO used by these programs | JSR to `$FFEF`; model supplies a narrow stub |

A raw CPU BRK saves a return PC of BRK+2 and status before dispatching through
the vector. The course world stops before executing BRK; T12 demonstrates the
instruction directly in Py65. JSR/RTS, BRK/RTI, RESET and warm entry must not be
used interchangeably.

## Sources and implementation checks

The primary instruction reference is MOS Technology's
[*MCS6500 Microcomputer Family Programming Manual*, January 1976](https://www.bitsavers.org/components/mosTechnology/6500-50A_MCS6500pgmManJan76.pdf).
The repository's installed `py65==1.2.0` NMOS implementation
(`py65/devices/mpu6502.py`) provides the executable model. Its
[upstream source](https://github.com/mnaberez/py65/blob/1.2.0/py65/devices/mpu6502.py)
is a model implementation, not a hardware datasheet. The Briel manual's
Appendix C, printed/PDF pages 30–32, supplies the Monitor listing; see the
[manual checks and errata](../review.md#manual-checks).
